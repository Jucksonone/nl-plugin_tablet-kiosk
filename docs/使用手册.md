# 平板终端 使用手册

插件 `tablet_kiosk` 0.2.2 · Natural Land 平台插件

平板终端是一台放在场地里或场地旁边的 Linux 平板。它可以：

- **全屏显示刺激素材**：视频、图片、音频，或者白屏、黑屏、熄屏；
- **采集**：摄像头视频、三条麦克风音轨、屏幕触摸；
- **跟随平台录制**：实验开启"平板方案"后，平台每次录制，平板都自动开始采集，录制结束时自动停止，文件归入那条记录。

所有操作都在平台网页里完成，不用到平板上操作。

## 1. 界面在哪里

插件在平台里有 4 个入口：

| 位置 | 名称 | 用途 |
|---|---|---|
| 侧栏 → 系统设置 → **平板终端** | 系统页 | 平板状态、手动控制、手动采集、素材库、全部采集记录、事件、连接设置 |
| 实验页 → **平板终端** 标签 | 实验标签 | 编辑本实验的平板方案；查看本实验的采集 |
| 记录详情 → **平板采集** 标签 | 记录标签 | 这条记录用的方案、采集文件、回放、导出、事件 |
| 实时监控 → **平板终端** 卡片 | 实时卡片 | 平板是否在线、是否在采集、屏幕显示什么、电量 |

系统页有 5 个标签：**概览、素材、采集记录、事件、设置**。

## 2. 第一次使用：连接平板

> 如果插件已经由管理员设置好（概览页显示"平板在线"），跳过这一节。

### 2.1 在插件里填平板地址

1. 打开 系统设置 → 平板终端 → **设置**。
2. 勾选 **启用（插件连接并控制平板）**。
3. **平板地址**：填平板的 IP，例如 `192.168.31.21`。在平板上打开终端，运行 `hostname -I` 可以看到。
4. **端口**：一般不用改，默认 `8770`。
5. **令牌**：插件自动生成，平板要用同一个令牌，见 2.2。
6. **主机最少保留空间（GB）**：默认 20。主机剩余空间低于它时，插件暂停从平板取回文件，见第 11 节。
7. 点 **保存**。

### 2.2 把令牌写到平板上

设置页右边 **平板上的配置** 里有两行，例如：

```toml
token = "nVZ9Sm5V…"
listen_port = 8770
```

把这两行写进平板的 `~/.config/kiosk/config.toml`，然后在平板上运行：

```bash
systemctl --user restart kiosk-agent
```

回到 **概览**，几秒内应显示平板的状态（屏幕、音量、电量等）。如果显示"平板没有响应"，见 [常见问题](#14-常见问题)。

> 改了令牌以后，平板上的配置也要一起改，否则插件连不上。

## 3. 上传素材

素材是平板上显示的文件，存在插件的**素材库**里，所有实验共用。

1. 系统设置 → 平板终端 → **素材**。
2. 点 **上传素材**，可以一次选多个文件。
   - 支持：视频（mp4、mkv、webm、mov、avi、m4v）、图片（jpg、png、webp、bmp、gif）、音频（mp3、wav、ogg、flac、m4a、opus）。
   - 单个文件最大 4 GB。上传时显示进度。
3. 上传完成后出现在列表里：
   - **已在平板**："是"表示平板上已有这个文件，可以直接显示；"否"表示还没传过去。
   - **使用的实验**：哪些实验的当前方案用到了它。
   - 点文件名可以预览。

**素材什么时候传到平板？** 不需要手动传：

- 实验方案开启采集时用到的素材，插件每分钟检查一次，提前传过去；
- 手动显示或手动采集用到平板上没有的素材时，插件会先传，并提示"素材正在传到平板"，稍等几秒再点一次即可；
- 也可以点 **传到平板** 立刻传。

**删除素材**：点 **删除**。实验方案正在使用的素材删不掉，要先从方案里移除。删除素材不影响已有的采集记录。

> 同一个文件重复上传只会存一份（按文件内容识别）。

## 4. 给实验设置平板方案（随录制采集）

每个实验有一份**平板方案**，决定这个实验录制时平板做什么。

1. 打开实验页 → **平板终端** 标签。
2. 勾选 **随录制采集**。
3. **采集内容**：勾选 **摄像头视频**、**麦克风音频**、**触摸**，至少选一项。
4. **采集时设置屏幕显示**（可选）：
   - 不勾选：采集时平板保持当前的显示；
   - 勾选后选择 **屏幕**：
     - **播放素材**：从素材库添加到 **播放列表**，可以调整顺序（↑ ↓）或移除（✕）；
     - **白屏**、**黑屏**；
     - **熄屏**：屏幕断电，但触摸仍然采集。
   - **循环播放**：播放列表放完后从头再来。
   - **每张图片显示（秒）**：列表里有多个文件时，每张图片停留的时间。
   - 列表里只有一个素材时：视频循环播放，图片一直显示。
5. **音量**、**亮度**（可选）：勾选后拖动滑块设置；不勾选就保持平板当前的设置。
6. **结束后恢复原来的屏幕、音量和亮度**：建议保持勾选。
7. 点 **保存方案**。

**版本**：每次保存生成一个新版本（右上角显示 `v3 · 谁 · 何时`），**历史版本**里可以看到以前的版本。每条录制用的是它开始时的版本，之后再改方案不影响已经录完的记录。

**关闭**：取消勾选 **随录制采集** 再保存，之后的录制平板就不采集了。

> 两个人同时修改同一个实验的方案时，后保存的人会收到"方案已被修改"的提示，刷新后重新修改即可。

## 5. 录制时会发生什么

在平台上开始录制以后：

1. 插件每秒检查平台是否在录制。看到新的录制后，读出这个实验当前的平板方案。
2. 如果方案开启了采集：
   - 平板按方案切换屏幕、音量和亮度；
   - 开始采集，采集名是 `<记录号>.p1`；
   - 方案用到的素材如果还不在平板上，先传过去再开始，状态显示"正在把素材传到平板"。
3. 录制期间，插件每 5 秒给平板续一次"租约"（见第 10 节）。
4. 平台停止录制后，插件让平板停止采集，平板恢复原来的屏幕、音量和亮度。
5. 文件陆续取回到主机。全部取回后，采集状态变为 **已完成**。

**分段**：如果平板在录制中途自己停了（例如平板重启、网络断了超过 30 秒），插件在 10 秒后开始下一段（`.p2`、`.p3`……）。每段都归到同一条记录下。

**注意**

- 插件不能阻止或推迟平台录制。平板离线时平台照常录制，只是这次没有平板数据，事件里会记下原因。
- 录制开始时插件没在运行（例如主机刚重启）的话，插件发现录制后会马上补上采集。方案按录制开始时的版本推算，界面上标注"按开始时的方案推算"。录制开始到插件发现之间的这段时间没有平板数据。

## 6. 手动控制与手动采集

都在 系统设置 → 平板终端 → **概览**。

### 6.1 手动控制

| 控件 | 作用 |
|---|---|
| 音量、亮度滑块 | 松开鼠标后生效 |
| 屏幕：播放素材 / 白屏 / 黑屏 / 熄屏 | 切换显示模式 |
| 播放：上一个 / 暂停 / 继续 / 下一个 | 控制播放列表 |
| **显示素材** | 选好播放列表后点 **在平板上显示** |

采集中也可以手动控制，改动会记进事件日志和这次采集的屏幕记录。

### 6.2 手动采集

不跟随录制的单次采集，适合调试、预实验或单独测试。

1. 填 **时长（分钟）**，最长 6 小时。
2. 选采集内容、屏幕、音量、亮度，用法和实验方案一样。
3. 点 **开始采集**。
4. 到时间自动停止。想提前结束，点 **当前采集** 卡片上的 **停止采集**。

以下情况不能手动采集：

- 平台正在录制，而且实验方案开启了采集。这时平板在为录制采集，录制的采集也不能手动停止，只会随录制结束而停止；
- 平板已经在采集。

平台录制、但实验方案没开采集时，可以手动采集，这次采集会记上当时的记录号。

## 7. 查看、回放和导出采集数据

### 7.1 找到采集

- **某条记录的采集**：记录详情 → **平板采集**。页面上还会显示这条记录用的方案版本和事件。
- **某个实验的采集**：实验页 → 平板终端 → **本实验的采集**。
- **全部采集**：系统设置 → 平板终端 → **采集记录**，可以按类型（随录制 / 手动 / 其他）筛选。

列表里的状态：

| 状态 | 含义 |
|---|---|
| **采集中** | 平板正在录 |
| **取回中** | 已经录完，但还有文件在平板上没取回来 |
| **已完成** | 所有文件都已取回主机 |

### 7.2 一次采集的详情

点列表中的一行展开：

- **时长、视频段、触摸、音量 / 亮度**：触摸是触摸次数（下面是原始帧数）；音量和亮度是采集开始时的值；
- **回放**：视频按段保存，每段约 10 秒。点段号播放，播放器默认播第 1 条音轨；
- **屏幕记录**：每次屏幕切换的时间（相对采集开始）、模式和素材名；
- **全部文件**：可以单独下载每个文件。

### 7.3 触摸

采集了触摸时，采集详情里有 **触摸** 一节（记录详情 → 平板采集里打开即可看到）：

- **数字**：
  - **触摸次数**：手指按下一次算一次，点一下和滑一下都算一次，两根手指同时按算两次；
  - **按压总时长**：所有触摸按住时间的总和；
  - **最多同时手指**；
  - **最后一次触摸**：相对采集开始的时间。
- **屏幕分布图**：一个 16:10 的框代表平板屏幕（左上角就是屏幕左上角）。
  - 圆点是手指按下的位置，线是手指移动的轨迹；
  - 颜色表示时间，浅色早、深色晚，图例在左上方。深色模式下反过来：越晚越亮；
  - 鼠标停在圆点上，显示第几次、什么时间、按了多久、起点坐标、移动距离；
  - 点圆点，回放会跳到那一刻的视频；
  - 整次采集只显示同一张图片时，图片会淡淡地画在背景里，方便看触摸落在图片的哪个位置。
- **时间轴**：每根柱子是一段时间内的触摸次数，时间间隔随采集长短自动选择（5 秒、10 秒、1 分钟……）。
  - 虚线是屏幕切换的时刻，鼠标停上去显示切换后的内容；
  - 点柱子，回放跳到那段时间的视频。
- **和回放联动**：播放某段视频时，
  - 时间轴上用灰底标出这一段，竖线跟着播放位置走；
  - 分布图默认只显示这一段的触摸，其他触摸变成灰点；取消勾选"只显示正在播放的这段视频"可以看全部；
  - 正在发生的触摸外面会加一个圈。
- **触摸明细**：展开后是每次触摸的时间、按压时长、起点、终点、移动距离和当时屏幕显示的内容。点一行，回放跳到那一刻。**下载 CSV** 是原始帧数据。

正在进行的采集，触摸数据每 10 秒左右更新一次。实时监控卡片上也会显示"本次采集触摸 N 次"。

> 按压时长按"按下的那一帧到抬起的那一帧"计算，触摸屏大约每 25 ms 报告一帧，所以很短的轻点显示为"< 0.03 s"。

### 7.4 导出

点 **导出 zip**，得到一个压缩包：

```
<采集名>/
  session.json         采集元数据
  av_00000.mp4 …       视频 + 音轨，每段约 10 秒
  touch_00001.jsonl …  原始触摸帧
  touch.csv            触摸数据表格
  stimulus/            这次采集中屏幕上显示过的素材原文件
  README.txt           文件说明和时间对齐方法
```

大的采集（几小时）导出需要一些时间，浏览器会边生成边下载。

## 8. 数据格式与时间对齐

### 8.1 视频和音频（`av_NNNNN.mp4`）

- 视频：H.264，默认 640×480。
- 音频：Opus，48 kHz 单声道，**三条音轨**：

| 音轨 | 内容 | 用途 |
|---|---|---|
| 1 | 麦克风（回声消除后） | 直接听，播放器默认播这条 |
| 2 | 播放参考：喇叭当时实际放出的声音 | 离线去回声、核对刺激声音 |
| 3 | 原始麦克风（未经回声消除和降噪） | 精细分析 |

离线去回声用"音轨 3 + 音轨 2"。提取某条音轨的例子：

```bash
ffmpeg -i av_00000.mp4 -map 0:a:1 reference.wav     # 第 2 条音轨（从 0 数）
```

### 8.2 触摸

`touch_NNNNN.jsonl` 里每行是一个触摸帧：

```json
{"t": 1792935471.123456, "touches": [{"id": 17, "x": 0.41, "y": 0.73}]}
```

- `t`：时间（Unix 秒）；
- `id`：手指编号，同一次按下保持不变；
- `x`、`y`：0～1 的屏幕比例坐标，原点在左上角；
- `touches` 为空表示所有手指都抬起了。

`touch.csv` 是展开后的表格，列为 `t_unix, t_rel, frame, contact_id, x, y`，其中 `t_rel` 是相对采集开始的秒数。

> **触摸帧不等于触摸次数**：一次点击会产生好几帧。界面上的"触摸次数"是按手指编号把帧合起来算的（见 7.3），"按下的帧"是至少有一根手指在屏幕上的帧数。

### 8.3 时间对齐

- 所有时间都是**平板时钟**的 Unix 时间（秒）。
- 视频和音频：`session.json` 里每段有 `start_utc`。段内某一帧的时间 = `start_utc` + 它在文件里的播放时间。
- 屏幕显示：`session.json` 的 `screen.log` 记录每次切换（时间、模式、素材）；`screen.playback` 每秒记录一次"时间 → 素材视频播放到第几秒"，用来确定循环视频在任意时刻显示的是哪一帧。
- 和平台录像对齐时，注意平板时钟和主机时钟可能有差。**概览** 页的"平板时钟差"显示当前的差值，建议平板开启自动对时（NTP）。

## 9. 状态、事件和健康曲线

### 9.1 概览页

| 区域 | 内容 |
|---|---|
| 顶部数字 | 屏幕（模式和当前素材）、音量、亮度、电量、温度和内存、平板时钟差和 agent 版本 |
| **当前采集** | 平台是否在录制、本实验的方案、正在进行的采集 |
| 传输 | 平板上待取的文件、主机剩余空间、正在传的素材、正在取回的文件 |
| **平板健康** | 电量、温度、内存、负载曲线，可选 1 / 6 / 24 / 168 小时 |

### 9.2 事件

**事件** 标签记录发生过的事，最新的在最上面：

- 平板上线、离线；
- 请求开始采集、采集开始、采集结束、文件全部取回；
- 开始或停止采集失败、采集出错、采集被中断；
- 上传或删除素材、素材已传到平板；
- 手动控制、音量和屏幕的改变；
- 保存设置、保存实验方案；
- 主机空间不足或恢复。

出问题时先看这里，红色标记的是失败类事件。

### 9.3 采集结束的原因

| 原因 | 含义 |
|---|---|
| 录制结束 | 随录制采集的正常结束 |
| 到时结束 | 手动采集到了设定时长；或者录制的一段满了 24 小时 |
| 手动停止 | 有人点了"停止采集" |
| 插件失联，平板自行停止 | 插件 30 秒没有续租（主机、插件或网络出了问题），见第 10 节 |
| 中断（平板重启或断电） | 平板程序意外停止，最后约 10 秒的数据丢失 |
| 被新的采集替换 | 录制开始时有手动采集在跑，被录制的采集替换 |

## 10. 安全机制

**租约**：插件开始的每次采集都带一个 30 秒的租约，插件每 5 秒续一次。如果插件停了、主机关机或者网络断开，租约到期后平板会**自己停止采集**，并恢复原来的屏幕、音量和亮度。平板不会因为插件出了问题而一直录下去，也不会一直停在刺激画面上。

实测（2026-10-25）：停掉插件后 28 秒，平板自行停止了采集；插件重新启动后，自动把这次采集的文件取了回来。

**文件不会丢**：

- 平板上的文件要等插件确认在主机上存好以后才删除；
- 网络断开或主机空间不足时，文件先留在平板上，之后自动取回；
- 平板断电或重启时，只丢正在写的最后一段（约 10 秒），其余文件在平板启动后照常取回。

**不影响平台**：插件出任何问题，平台的录制、相机、数据库都照常工作。

---

## 11. 存储空间与删除

**数据量**：默认设置下约 **0.5 GB / 小时**（视频 1 Mbps + 三条音轨）。触摸数据很小。

**存放位置**：主机上的插件数据目录（例如 `~/natural-land-data/plugins/tablet_kiosk/`）：

```
captures/<采集名>/   采集文件
media/               素材库
```

**不会自动删除**。需要的数据导出后，在采集详情里点 **删除**，删除不能恢复。

**空间不足时**：主机剩余空间低于设置里的"主机最少保留空间"时：

- 插件暂停取回文件，文件先留在平板上（平板剩余空间显示在概览页）；
- 概览页显示黄色提示，事件里记一条"主机空间不足"；
- 腾出空间后自动继续取回。

**唯一的自动删除**：在平台上删除了某条记录（或实验）后，插件会在一小时内删掉这条记录的平板采集（以及这个实验的方案）。平台暂时连不上时不会删任何东西。

## 12. 平板的安装、更新与 kiosk 模式

> 这一节给管理员。详细步骤见仓库里的 [`tablet/README.md`](../tablet/README.md)。

### 12.1 安装或更新平板程序

在有本仓库的电脑上运行（把地址换成平板的）：

```bash
TABLET=lilab@192.168.31.21
rsync -a --delete --exclude __pycache__ tablet/ $TABLET:~/kiosk/device/
ssh -t $TABLET 'cd ~/kiosk/device && sh deploy/install.sh'   # 只有第一次需要（要 sudo）
ssh $TABLET 'systemctl --user restart kiosk-agent'
```

重启平板程序时，正在进行的采集会先正常结束（最多等 30 秒）。概览页的"agent 版本"会显示新的版本号。

### 12.2 kiosk 模式

- `kiosk-mode on`：平板开机后自动进入只运行播放器的会话，没有桌面、任务栏，也不会弹系统通知。**正式实验时用这个。**
- `kiosk-mode off`：回到普通的 Xubuntu 桌面，方便维护。桌面会话里平板程序也会开机自动启动（`~/.config/autostart/kiosk-agent.desktop`），但可能弹系统通知；屏幕上有虚拟键盘 Onboard（点输入框自动弹出，也可点任务栏的键盘图标）。
- `kiosk-mode status`：查看当前模式。

切换模式会重启显示管理器，屏幕黑几秒。

### 12.3 平板上的其他设置

- **电源键**：短按无效，长按约 5 秒关机；合盖和挂起键都不起作用。
- **回声消除**：PipeWire 的 echo-cancel 模块（`deploy/60-echo-cancel.conf`）。
- **自动对时**：建议开启 NTP，保证时间对齐。

## 13. 问 Agent

平台的 Agent 可以读取插件的数据（只读，不能控制平板）。可以这样问：

- "平板现在在线吗？屏幕在显示什么？"
- "记录 xxx 的平板采集有几段？每段多长？为什么结束？"
- "这次采集里屏幕依次显示了哪些素材？"
- "这次采集触摸了多少次？显示每个素材的时候各触摸了几次？"
- "实验 3 的平板方案是什么？"
- "最近平板有没有离线或采集失败？"

Agent 报告的是触摸次数（按下一次算一次），不会把原始帧数当成触摸次数；它不知道是谁碰的屏幕。插件不分析视频和音频内容，只知道显示了什么和触摸的帧数。

## 14. 常见问题

**概览页显示"还没有设置平板的地址"**
到 **设置** 填地址并勾选启用，见第 2 节。

**显示"平板没有响应"**
1. 平板是否开机、是否连着和主机互通的网络。在主机上试 `nc -z 平板IP 8770`。
2. 平板程序是否在运行：在平板上运行 `systemctl --user status kiosk-agent`。
3. 令牌是否一致：错误信息里有 `bad_token` 就是令牌不对，按 2.2 重新写一遍。
4. 平板 IP 变了：在平板上运行 `hostname -I`，然后改插件设置。建议在路由器上给平板分配固定 IP。

**录制开始了，平板没有采集**
- 看 **当前采集**：如果显示"本实验没有平板方案"或"方案 vN：不采集"，去实验页开启方案；
- 显示"正在把素材传到平板"：素材较大，等传完；
- 显示"开始采集失败"：看 **事件** 里的错误原因，插件 30 秒后会自动重试。

**采集一直是"取回中"**
- 平板离线：恢复连接后会自动继续；
- 主机空间不足：见第 11 节；
- 采集很长、文件很多：取回需要时间，看概览页的"正在取回"。

**回放时不能拖动进度条**
平台代理不支持拖动，每段只有约 10 秒，按段回放即可。需要完整分析时请导出。

**屏幕上弹出了系统通知（例如电量提示）**
平板处在普通桌面会话里。切到 kiosk 模式（`kiosk-mode on`）就不会再弹。

**想把平板恢复成原来的独立版**
旧程序备份在平板的 `~/kiosk/device.standalone-20261025`，配置备份在 `~/.config/kiosk/config.toml.standalone-20261025`。

## 15. 已知限制

- 时间都按平板时钟记录，与平台录像对齐时要考虑时钟差（概览页有显示）。
- 平板断电或重启时，最后约 10 秒的采集会丢失。
- 回放不能拖动进度，完整数据请导出。
- 插件不能阻止平台录制：平板离线时，平台照常录制，这条记录就没有平板数据。
- 平板程序和插件分开安装：改了平板端的代码，要按 12.1 单独更新平板。
- 平板在 Wi-Fi 下取回文件的速度受网络影响。长时间录制时文件会在平板上积压一会儿，录完后会继续取回。
